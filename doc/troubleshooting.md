# 域名解析/访问问题排查指引

> 适用于 `*.ptrel.cc.cd`（dnshe）与 `*.ptrel.asia`（阿里云）域名"解析不了 / 连不上"的排查。
> 核心原则：**分层排查**——DNS 解析层 → 服务器链路层 → 外部设备网络层，避免误判。

## 一、排查顺序（必看）

```
1. 权威 DNS 能否解析（确认记录存在）
2. 公共 DNS 能否解析（确认缓存已同步）
3. 服务器 IPv6 链路是否正常（确认服务器侧无问题）
4. 外部设备网络 IPv6 是否可用（确认问题是否在外部）
```

## 二、具体命令

### 1. 权威 DNS 解析

```bash
# dnshe 权威
dig @ns7.dnshe.com <域名> AAAA
# 阿里云权威
dig @ns1.alidns.com <域名> AAAA
# 公共 DNS
dig @114.114.114.114 <域名> AAAA
```

**有记录 → 继续第 2 步；无记录 → DDNS 或 dnshe/阿里云侧问题。**

### 2. 服务器 IPv6 链路

```bash
# 本机 IPv6 出口（应 0% 丢包）
ping -6 -c 3 2400:3200::1          # 阿里 DNS IPv6
ping -6 -c 3 2001:4860:4860::8888  # 谷歌 DNS IPv6

# 本机 IPv6 地址（240e 前缀 = 电信原生；2001: 前缀 = 隧道，异常）
ip -6 addr show | grep "scope global"

# 本机监听端口（应见 [::]:80 [::]:443）
ss -tlnp6 | grep -E ":80 |:443 "

# IPv6 防火墙（应为 ACCEPT）
sudo ip6tables -L INPUT -n
```

### 3. 服务器自测域名访问

```bash
# 经 IPv6 访问域名（本机=目标时必通，用于确认 nginx 正常）
curl -6 -sk -o /dev/null -w "%{http_code}\n" https://<域名>/
```

### 4. 外部设备网络（在外部设备上执行）

**test-ipv6 报告判读：**

| 测试项 | 通过 | 失败含义 |
|--------|------|---------|
| IPv4 域名连接 | ✅ | 设备 IPv4 正常 |
| IPv6 域名连接 | ❌ 立刻失败(0.0xx s) | **设备 IPv6 出口不可用**（非超时） |
| 双栈域名连接 | ✅ 使用 ipv6 | 设备有 IPv6 地址 |
| IPv6 大数据包 | ❌ | PMTUD/MTU 问题 |

**关键判据**：`IPv6 域名连接测试` **立刻失败（0.009s 左右）** = 设备拿到地址但发不出 IPv6 流量 = **外部设备所在网络（路由器/运营商）问题**，不是服务器/DNS/DDNS 问题。

**设备侧排查：**
```cmd
:: Windows
ipconfig                      :: 看是否有 IPv6 地址、是否 240e 开头
nslookup <域名>               :: 看解析结果
ping -6 240e:390:3c7:ef00::8a8
```
```bash
# macOS/Linux
ipconfig getifaddr en0       # 或 ip -6 addr
dig <域名> AAAA
ping6 240e:390:3c7:ef00::8a8
```

**最有效的排除法**：外部设备关 WiFi 改用**手机流量**再跑 test-ipv6
- 流量下 IPv6 正常 → **路由器问题**（查路由器 IPv6 开关/防火墙/前缀委派 PD）
- 流量下也失败 → 设备本身或运营商问题

## 三、2026-08-15 实测结论（重要）

1. **服务器侧全部正常**：原生 240e IPv6、防火墙 ACCEPT、80/443 监听、curl -6 自测 301
2. **外部设备问题**：test-ipv6 实测"有 IPv6 地址但纯 IPv6 域名立刻失败" → 外部设备 IPv6 出口不可用
3. **宽带 IPv4 是 NAT**：`115.197.187.231` 公网 80/443 不可达（阿里云公网实测），公网访问全靠 **frp + 阿里云反代**
4. **已做双栈**：所有域名加 A 记录（指向 115.197.187.231），外部 IPv6 坏时可 fallback IPv4；但公网访问仍需 frp/nginx 反代

## 四、常见误区

- ❌ "加阿里云 NS 到 dnshe 面板" → 多 NS 不同步会解析不一致，且 `.cc.cd` 免费域名不允许
- ❌ "A 记录指向内网 IP 让内网设备访问" → 公网设备解析到私网地址彻底连不上；单域名无法对内/对外返回不同 IP（需 split DNS）
- ❌ "dnshe 记录名带下划线" → 400 必失败（A/AAAA 不允许下划线），用连字符
